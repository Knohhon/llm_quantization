# GGUF Quantization — Live Demo

Терминальные эксперименты с готовыми GGUF-весами Qwen2.5-1.5B-Instruct:
F16, Q8_0, Q6_K, Q4_K_M и Q2_K. Сравниваются размер файла, peak RSS,
prefill, decode, ответы на одинаковые задания и perplexity. Используются Bash,
Python со стандартной библиотекой и существующая сборка llama.cpp. Общего
запускающего скрипта и автоматической оркестрации нет.

## Окружение и настройка

Нужны Ubuntu/WSL2, Bash, Python 3.8+, `lscpu` и GNU `/usr/bin/time`, а также
`llama-cli`, `llama-bench`, `llama-perplexity`. Дополнительные Python-пакеты не нужны.
Скрипты запускаются из любого каталога; относительные пути разрешаются от проекта.

Параметры находятся в [config.env](config.env). По умолчанию:

```bash
LLAMA_BIN_DIR="$HOME/llama.cpp/build/bin"
THREADS=4
CONTEXT_SIZE=2048
PROMPT_TOKENS=512
GENERATION_TOKENS=128
MAX_NEW_TOKENS=256
REPETITIONS=3
SEED=42
```

Путь соответствует обнаруженной установке. На CPU Intel Core i5-12450H WSL
показывает 12 логических CPU; для всех вариантов оставлены одинаковые 4 потока.
Сборка уже работает, переустановка и пересборка не требуются.
Параметры можно править в файле или переопределять переменными окружения:

```bash
THREADS=6 bash scripts/benchmark.sh
LLAMA_BIN_DIR=/another/build/bin bash scripts/compare_generation.sh "What is 2 + 2?"
```

Дополнительно доступны `QUANTS`, `KV_CACHE_TYPE=f16`, `LOAD_MODE=mmap`
(`none` отключает mmap), `PPL_CONTEXT_SIZE=512`, `PPL_CHUNKS=-1` (весь корпус).
`QUANTS` принимает имена через пробел или запятую. Если F16 не выбран, скорости
измеряются, но ускорение и изменение PPL относительно F16 выводятся как N/A.
Для размера нужен файл F16 даже при выборе подмножества моделей.

## Скачивание

```bash
bash scripts/download.sh
```

Источник — [bartowski/Qwen2.5-1.5B-Instruct-GGUF](https://huggingface.co/bartowski/Qwen2.5-1.5B-Instruct-GGUF/tree/9eadc66189c7641e1ddd226b8267a9119b2ce2d4),
revision `9eadc66189c7641e1ddd226b8267a9119b2ce2d4`.
Наличие пяти точных имён и LFS SHA-256 проверено по
[API репозитория](https://huggingface.co/api/models/bartowski/Qwen2.5-1.5B-Instruct-GGUF/revision/9eadc66189c7641e1ddd226b8267a9119b2ce2d4?blobs=true).
Имена, размеры и контрольные суммы зафиксированы в `scripts/models.json`.
Baseline опубликован с суффиксом **`-f16.gguf`**, в нижнем регистре.
Все файлы относятся к одной исходной Qwen/Qwen2.5-1.5B-Instruct.
Самостоятельная конвертация и квантизация не выполняются.

Загрузчик сначала проверяет размер и SHA-256 локальных файлов. Корректные файлы
не скачиваются повторно; если всё уже скачано, сетевых обращений нет. Для
недостающих файлов сначала проверяются имена, размеры и SHA-256 через API
зафиксированной revision, затем скачиваются веса. Файл `.part` переименовывается
в `.gguf` только после проверки целостности. При повторном запуске незавершённый
файл скачивается заново. Всего нужно около 7.15 GiB свободного места плюс запас
для `.part`, если заменяется повреждённый файл. Веса исключены из Git.

Для подготовки подмножества:

```bash
QUANTS="F16 Q4_K_M" bash scripts/download.sh
```

Если веса перенесены вручную, используйте точные имена из manifest и запустите
`download.sh` для проверки SHA-256. Эксперименты проверяют наличие, размер и
сигнатуру GGUF; повторное чтение всех гигабайтов для хеширования перед каждым
измерением намеренно не выполняется, чтобы не прогревать файловый кеш.

## Независимые эксперименты

```bash
# Фактический размер файлов, сжатие и сокращение относительно F16
bash scripts/compare_size.sh

# Отдельные тесты prefill и decode, по три повтора
bash scripts/benchmark.sh

# Короткая версия для выступления
QUANTS="F16 Q4_K_M Q2_K" REPETITIONS=1 bash scripts/benchmark.sh

# Максимальный RSS отдельного llama-cli через /usr/bin/time -v
bash scripts/compare_memory.sh

# Одинаковое задание всем выбранным моделям
bash scripts/compare_generation.sh "Write a Python function for binary search."

# Без аргумента используется фиксированное задание из common.py
bash scripts/compare_generation.sh

# Более долгий эксперимент для предварительной подготовки
bash scripts/perplexity.sh

# Быстрая проверка PPL на одном блоке для всех выбранных моделей
PPL_CHUNKS=1 bash scripts/perplexity.sh

# Сводка сохранённых измерений, допускает отсутствие любых экспериментов
python3 scripts/summary.py
```

В `data/prompts.txt` есть задания на Python, математику, логику, JSON и следование
инструкциям. Выбирайте задания заранее и показывайте полные ответы всех моделей.
Они не подобраны исключительно для ухудшения результатов низкобитных вариантов.
Скорость из generation сохраняется отдельно; сводка использует сопоставимые
синтетические тесты llama-bench, а не скорость ответов разной длины.

Результаты:

| Скрипт | Выходные файлы |
| --- | --- |
| `compare_size.sh` | `results/size.csv` |
| `benchmark.sh` | `results/benchmark.csv`, исходный JSON для каждой модели |
| `compare_memory.sh` | `results/memory.csv`, полные отчёты GNU time |
| `compare_generation.sh` | `results/generations/<UTC>/`, `results/generation.csv` |
| `perplexity.sh` | `results/perplexity.csv` |
| `summary.py` | `results/summary.csv`, `results/summary.md`, таблица в терминале |

Каждый успешный запуск заменяет текущий CSV эксперимента целиком. Старые строки
не подмешиваются. Исходные stdout/stderr, команды, CSV и метаданные каждого запуска
остаются в `results/raw/<experiment>/<UTC>/`; для генерации — в
`results/generations/<UTC>/`. Ответы сохраняются вместе с полным stdout llama-cli,
который может содержать служебные сообщения и строку скорости. Промпт хранится
отдельно. Ошибки inference не записываются как числовые результаты.

Файлы `*.meta.json` содержат параметры, CPU, ОС, версии и SHA-256 исполняемых
файлов llama.cpp, revision моделей и SHA-256 корпуса. Поддержка используемых
флагов проверяется через `--help` перед запуском. Реализация проверена по справке
build 12733, commit `de3069728`; требуются `--load-mode` и перечисленные CPU-флаги.
Неподдерживаемая версия завершается с понятным сообщением.

Сводка проверяет контрольную сумму входного CSV и совместимость настроек
memory/benchmark/perplexity: CPU, ОС, сборку, потоки, контекст, KV, mmap, длины
тестов, повторы и корпус. Сравнение намеренно строгое: после короткого запуска
с `REPETITIONS=1` нельзя объединить его с memory/PPL, сохранёнными при
`REPETITIONS=3`. Повторите нужные эксперименты с одинаковой конфигурацией и
переменными окружения. Выбор `QUANTS` может различаться; отсутствующие измерения
останутся N/A. Статический размер файла допускается объединять независимо от
параметров inference при совпадении manifest моделей. Ответы на произвольные
промпты в сводку не включаются.

## Методология

Все inference-команды получают `-ngl 0`, `--device none`, запрет offloading KV и
операций на GPU. Для CLI/PPL заданы одинаковые потоки обработки промпта и decode.
Используется `f16` для K/V, явно заданный mmap и отключённый lazy loading.
Параметры загрузки одинаковы для всех вариантов. Переменные `LLAMA_ARG_*`
исключаются из окружения дочерних процессов, чтобы не переопределять эксперимент.
После подготовки файлов сетевые обращения экспериментам не нужны: передаются
только локальные пути и `--offline`, когда этот флаг поддерживается.

* **Размер**: `stat().st_size / 2^20`, MiB логического содержимого файла.
  Compression = bytes(F16) / bytes(quant); reduction = 100 × (1 − bytes(quant) /
  bytes(F16)). Это не выделенное файловой системой место и не потребление RAM.
* **Prefill / decode**: llama-bench выполняет отдельные pp512 и tg128,
  по `REPETITIONS` повторов, с обычным встроенным прогревом. Из его JSON берутся
  `avg_ts` и `stddev_ts`, вычисляются оба ускорения относительно F16 этого же
  запуска. Таблица показывает SD, не доверительный интервал. При одном повторе
  SD не описывает вариативность. В llama-bench контекст каждого отдельного теста
  определяется его длиной (`n_prompt + n_gen`); `CONTEXT_SIZE` относится к CLI,
  а `PPL_CONTEXT_SIZE` — к perplexity. Эти три вида измерений имеют разные задачи.
* **Peak RSS**: максимум RSS процесса по GNU time, KiB переводятся в MiB делением
  на 1024. Используются один и тот же промпт, ChatML, greedy, контекст и ровно
  `GENERATION_TOKENS` выходных токенов (`--ignore-eos`). Генерация для оценки
  качества, наоборот, останавливается по EOS и ограничена `MAX_NEW_TOKENS`.
  RSS включает затронутые страницы mmap, KV и рабочие буферы, но не равен
  размеру файла и не описывает полное системное потребление памяти. Резидентность,
  общий page cache и давление памяти меняют RSS; эта метрика не изолирует только
  веса. GNU time не суммирует одновременный RSS произвольного дерева процессов.
* **Качество**: `--temp 0`, фиксированный seed, встроенный шаблон `chatml` для всех
  моделей, один пользовательский промпт, контекст 2048, максимум 256 новых токенов.
  Greedy делает выбор детерминированным в данной сборке, но не гарантирует
  побитовое совпадение на другом CPU/сборке. Короткие примеры дают качественное
  наблюдение, а не статистическую оценку способностей модели.
* **Perplexity**: меньше — лучше на данном корпусе; изменение =
  100 × (PPL(quant) / PPL(F16) − 1). Парсится только `Final estimate: PPL`,
  промежуточные оценки не принимаются за результат. Требуется не менее двух
  контекстов текста. Все модели получают одинаковые байты, контекст и число
  блоков; это raw text без chat template.

Фиксированный публичный корпус `data/perplexity.txt` — полный английский текст
[GNU GPL version 3, 29 June 2007](https://www.gnu.org/licenses/gpl-3.0.txt),
локальная копия `/usr/share/common-licenses/GPL-3` (35 149 байт, 5 644 слова).
SHA-256: `3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`.
Текст лицензии разрешает распространение неизменных копий; уведомление сохранено
в корпусе. Это разрешённый спецификацией альтернативный небольшой публичный
корпус, доступный без дополнительного скачивания. Его юридический домен узок:
PPL здесь нельзя сравнивать с опубликованными числами WikiText-2 или считать
общей оценкой instruction following. Использование всего корпуса зафиксировано
по умолчанию; при смене корпуса следует заново провести все PPL-измерения.

WSL2 разделяет ресурсы с Windows. Фоновая нагрузка, температура, частота CPU,
планировщик, swap и состояние файлового кеша влияют на результаты. Выполняйте
эксперименты последовательно, закройте тяжёлые приложения и используйте питание
от сети. Прогрев llama-bench не означает, что RSS измерен после холодной загрузки.
Не требуется очищать системный page cache или запускать команды от root.

## Краткая теория

Effective bits per weight — реальное число бит хранения на параметр: вместе
с полезными значениями приходится хранить масштабы, смещения и часть тензоров
в более высокой точности. Поэтому Q4_K_M не означает ровно 4 бита для каждого
параметра. Оценка `8 × размер файла / число параметров` также включает метаданные
GGUF и даёт только приблизительную эффективную плотность хранения.

Block quantization группирует веса в блоки с общими параметрами восстановления.
Более короткие представления уменьшают объём чтения, но вносят ошибку округления.
Загрузка весов и их деквантизация создают разный баланс затрат в разных ядрах CPU.

Memory bandwidth — скорость переноса данных из RAM. Decode для одного потока
часто memory-bound: на каждый следующий токен приходится читать значительную
часть весов. Уменьшение весов может ускорить этот этап. Prefill обрабатывает много
входных токенов параллельно и лучше переиспользует веса в матричных операциях;
он чаще приближается к compute-bound режиму, ограниченному вычислениями.
Это тенденции, а не гарантии: конкретные kernels, кеши и длины входа важны.

Деквантизация тоже требует операций и не всегда компенсируется сокращением
чтения памяти. Поэтому меньшая модель не обязана оказаться самой быстрой.
Итоговый компромисс Speed / Memory / Quality нужно устанавливать измерениями:
меньше веса и RAM, возможное ускорение и возможное ухудшение ответов/PPL.

## Сценарий выступления

1. Заранее скачать веса, выполнить memory и perplexity, подготовить benchmark
   со стабильными настройками. Проверить отсутствие фоновой нагрузки.
2. Показать `config.env`, CPU и зафиксированную сборку из метаданных.
3. Запустить `compare_size.sh`, объяснить compression и reduction.
4. Запустить сокращённый benchmark, сравнить prefill и decode. Если планируется
   объединять его с подготовленными данными, использовать те же настройки.
5. Передать одно из заданий `compare_generation.sh`, сравнить правильность,
   формат и соблюдение инструкций без предположения о победителе заранее.
6. Показать сохранённые RSS и PPL и запустить `summary.py` для совместимых данных.
   Обсудить наблюдаемый компромисс, ограничения корпуса и вариативность CPU.

## Проверка реализации и состояние этой подготовки

```bash
python3 -m unittest discover -s tests -v
for script in scripts/*.sh; do bash -n "$script"; done
python3 -m compileall -q scripts tests
```

Проверены расчёты размеров/сжатия, разбор отдельных pp/tg и ускорений,
относительная PPL, форматы строки скорости, N/A и отказ при несовместимых
метаданных или изменённом CSV. Синтетические fixtures используются только внутри
тестов во временном каталоге и не являются экспериментальными результатами.

В текущей ограниченной среде выполнены проверки `--help`/`--version` всех трёх
настоящих утилит, синтаксиса, расчётов, запуска сводки и понятных ошибок при
отсутствии моделей. Обнаружено 7.6 GiB RAM; полные сведения сохранены в
`results/environment.json`. Подробности проверки аргументов реальными бинарными
файлами — в `results/argument-smoke.json`.

**Загрузка и реальные сравнительные измерения пока не выполнены.** Запуск
`download.sh` завершился DNS-ошибкой `Temporary failure in name resolution`;
сообщение сохранено в `results/download.log`. Готовых весов в проекте нет.
Поэтому size, RSS, throughput, ответы и PPL не получены. Сводка сформирована с
N/A во всех ячейках измерений; размеры из Hugging Face manifest не подставляются
вместо измерений локальных файлов.

Дополнительно build 12733 использует в `llama-cli` внутренний локальный сервер.
В этой среде он завершился с `failed to get a free port` ещё до открытия модели.
Это блокирует memory и generation независимо от наличия весов. Сами
llama-bench и llama-perplexity принимают собранные аргументы и доходят до попытки
открытия отсутствующего GGUF.

Для завершения подготовки запустите `download.sh` в обычном WSL-терминале с DNS
и доступом к Hugging Face. Для CLI необходима возможность открывать локальный
слушающий порт; проверьте ограничения контейнера/песочницы, если ошибка повторится.
Затем независимо выполните приведённые выше скрипты экспериментов с одинаковыми
настройками и `summary.py`. Повторная сборка llama.cpp для устранения этих
ограничений не выполнялась.
